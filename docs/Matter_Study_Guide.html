1. Matter란 무엇인가

Matter는 CSA(Connectivity Standards Alliance, 구 Zigbee Alliance)가 주도하고 Apple·Google·Amazon·Samsung 등이 공동 개발한 스마트홈 표준 응용 프로토콜이다. 2022년 10월 1.0 발표 이후 매년 2회(봄/가을) 버전이 갱신된다.

탄생 배경 — 무엇을 해결하나

기존 문제Matter의 해법
생태계 파편화 — HomeKit/Google/Alexa/SmartThings 별로 따로 인증·개발 하나의 기기가 모든 생태계에서 동작 (멀티 어드민: 한 기기를 여러 생태계에 동시 등록)
클라우드 의존 — 인터넷 끊기면 제어 불가, 응답 지연 로컬 IPv6 통신 우선 — 같은 네트워크 안에서 직접 제어
프로토콜 난립 (Zigbee/Z-Wave/BLE/독자 RF) 전송 계층을 IP 기반(Wi-Fi/Thread/Ethernet)으로 통일
보안 수준 제각각 기기마다 공장 주입 인증서(DAC) 의무 — 위조 기기 차단

버전 히스토리 (주요)

버전시기주요 추가
1.02022.10조명, 스위치, 플러그, 센서, 도어락, 커튼, 온도조절기, 미디어 등 최초 디바이스 타입
1.22023.10가전 확장 — 냉장고, 세탁기, 식기세척기, 로봇청소기, 공기청정기 등
1.32024.05에너지 관리(EV 충전기), 전자레인지/오븐, 물 관리
1.42024.11배터리 저장장치, 히트펌프, 태양광, 라우터/액세스포인트(HRAP), Enhanced Multi-Admin
참고: 조명(Dimmable/Color Temperature Light)은 1.0부터 완전 지원되는 가장 성숙한 카테고리다. ON/OFF·CCT·DIM 제어는 모두 표준 클러스터로 커버된다.

2. 프로토콜 스택 구조

Matter는 응용 계층 표준이다. 자체 무선 기술이 아니라, 기존 IP 네트워크 위에 올라간다.

┌─────────────────────────────────────────────────────┐ │ Application 조명·스위치 등 디바이스 로직 │ ├─────────────────────────────────────────────────────┤ │ Data Model Node / Endpoint / Cluster / │ │ Attribute / Command / Event │ ├─────────────────────────────────────────────────────┤ │ Interaction Model Read / Write / Invoke / │ │ Subscribe (구독·보고) │ ├─────────────────────────────────────────────────────┤ │ Security PASE / CASE 세션, AES-CCM 암호화│ ├─────────────────────────────────────────────────────┤ │ Transport TCP / UDP (+ MRP 신뢰성 계층) │ ├─────────────────────────────────────────────────────┤ │ Network IPv6 ← 반드시 IPv6 │ ├─────────────────────────────────────────────────────┤ │ Link Wi-Fi │ Thread(802.15.4) │ Eth │ │ (BLE는 커미셔닝 전용) │ └─────────────────────────────────────────────────────┘

전송 수단별 역할

링크용도특징
Wi-Fi운영 트래픽대역폭 큼, 전력 소모 큼 — 상시전원 기기(가전, 허브)
Thread운영 트래픽802.15.4 기반 저전력 IPv6 메시 — 조명·센서·배터리 기기. 보더라우터 필수
Ethernet운영 트래픽허브·브리지류
BLE커미셔닝 전용최초 등록 시에만 사용. 등록 후 BLE는 꺼짐 (운영 통신에 사용 안 함)
흔한 오해: "Matter 기기는 BLE로 제어된다" — ✕. BLE는 Wi-Fi 비밀번호/Thread 네트워크 키를 안전하게 넘겨주는 최초 등록 통로일 뿐이며, 이후 모든 제어는 IPv6 (Wi-Fi 또는 Thread) 위에서 이뤄진다.

3. 데이터 모델 — Node / Endpoint / Cluster

Matter 기기의 기능은 계층형 데이터 모델로 표현된다. Zigbee ZCL을 계승·확장한 구조다.

Node (기기 1대 = Matter 노드, Node ID 보유) ├─ Endpoint 0 ← 필수. 기기 관리용 (Basic Information, │ Network Commissioning, OTA 등 유틸리티 클러스터) ├─ Endpoint 1 ← 실제 기능 ① 예: Dimmable Light │ ├─ Cluster: On/Off (0x0006) │ ├─ Cluster: Level Control (0x0008) │ └─ Cluster: Color Control (0x0300) └─ Endpoint 2 ← 실제 기능 ② (한 기기에 여러 기능 가능)
개념정의예시
Node네트워크상 Matter 기기 1대. 커미셔닝 단위Matter 조명 기기 1대
Endpoint노드 안의 기능 단위. Device Type이 부여됨EP1 = Color Temperature Light
Cluster기능 블록 (속성+커맨드+이벤트의 묶음). Server(기능 보유)/Client(제어측) 역할 구분On/Off 클러스터
Attribute클러스터의 상태값. 읽기/쓰기/구독 가능OnOff(bool), CurrentLevel(0~254)
Command클러스터에 내리는 동작 요청Toggle, MoveToLevel
Event시점 기록이 중요한 사건 로그스위치 눌림, 재부팅

Device Type (조명 관련)

Device TypeID필수 클러스터
On/Off Light0x0100On/Off
Dimmable Light0x0101On/Off + Level Control
Color Temperature Light0x010COn/Off + Level Control + Color Control(CT 모드)
Extended Color Light0x010D위 + 색상(HSV/XY)
선택 기준: ON/OFF + DIM + CCT 조명이면 Color Temperature Light (0x010C)가 맞는 타입.

4. 핵심 클러스터 상세 (조명 3종)

4.1 On/Off Cluster (0x0006)

구분이름설명
AttributeOnOff (bool)현재 점등 상태
CommandOn / Off점등 / 소등
Toggle반전
OffWithEffect 등페이드 효과 소등 (옵션)

4.2 Level Control Cluster (0x0008) — 밝기(DIM)

구분이름설명
AttributeCurrentLevel0~254 (254=100%). null 가능
CommandMoveToLevel(level, transitionTime)지정 밝기로 (전환시간 0.1s 단위)
MoveToLevelWithOnOff레벨 이동 + 0이면 Off / >0이면 On 연동

4.3 Color Control Cluster (0x0300) — 색온도(CCT)

구분이름설명
AttributeColorTemperatureMireds현재 색온도. 단위 = Mired
ColorTempPhysicalMinMireds지원 최소 Mired (= 최대 K)
ColorTempPhysicalMaxMireds지원 최대 Mired (= 최소 K)
CommandMoveToColorTemperature(mireds, tt)지정 색온도로
⚠ Mired 변환 (실수 1순위): Mired = 1,000,000 / Kelvin — 역수 관계라 방향이 반대다.
6500 K(주광) = 154 mired, 5000 K = 200 mired, 3500 K(전구) = 286 mired, 2700 K = 370 mired.
즉 Mired가 작을수록 차가운 빛. 자체 CCT 스케일(예: 0~1000)로 변환할 때 반드시 뒤집어서 매핑할 것.

5. 커미셔닝 — 장치 등록 절차

커미셔닝은 새 기기를 사용자의 Fabric(하나의 생태계가 관리하는 보안 도메인)에 편입시키는 절차다.

[폰/chip-tool = 커미셔너] [신규 기기 = 커미셔니] │ │ ① BLE 광고 (discriminator 포함) │ ② QR코드/숫자코드 입력 │ │──── BLE 연결 ───────────────────────▶│ │ ③ PASE: 패스코드 기반 보안세션(SPAKE2+) │ ④ 기기 인증서(DAC) 검증 ─ 정품 확인 │ ⑤ NOC(운영 인증서) 발급 ─ Fabric 편입 │ ⑥ 네트워크 자격증명 전달 │ Wi-Fi: SSID/PW │ Thread: Dataset(네트워크 키) │ │ ⑦ Wi-Fi/Thread 접속, IPv6 획득 │ ⑧ CASE: 운영 보안세션 수립 (mDNS로 발견) │◀──── 이후 모든 제어는 IP 위에서 ────▶│

멀티 어드민 (Multi-Admin)

등록된 기기에 OpenCommissioningWindow를 열면 다른 생태계(Fabric)에도 추가 등록이 가능하다 (최대 5 Fabric). 예: Google Home에 등록한 조명을 Apple Home에서도 동시 제어. 각 Fabric은 독립된 NOC를 가지므로 상호 간섭이 없다.

⚠ 테스트 vs 양산: 위 기본값(20202021/3840)과 테스트 VID 0xFFF1은 개발 전용이다. 양산 시에는 CSA에서 Vendor ID를 발급받고, 기기마다 고유한 패스코드/QR을 esp-matter-mfg-tool로 생성해 factory 파티션에 구워야 하며, 생태계 앱에서 정식 인식되려면 CSA 인증 + DCL 등재가 필요하다.

6. 보안 모델 — 인증서 체계

기기 인증 (Device Attestation) — "정품인가?"

PAA (Product Attestation Authority) ← CSA가 관리하는 루트 CA └─ PAI (Product Attestation Intermediate) ← 제조사 중간 인증서 └─ DAC (Device Attestation Certificate) ← 기기 1대 1장, 공장 주입 + CD (Certification Declaration) ← CSA 인증 통과 증명

커미셔닝 ④단계에서 커미셔너가 DAC 체인을 검증한다. 개발 중에는 SDK에 내장된 테스트 인증서가 쓰이고, 양산 시 Espressif의 사전 프로비저닝 모듈을 쓰거나 자체 PAI를 발급받는다.

esp-matter 앱 코드 골격 (콜백 중심)

/* 속성이 바뀔 때마다 호출 — 여기서 실제 HW(또는 UART)를 구동 */
static esp_err_t app_attribute_update_cb(attribute::callback_type_t type,
        uint16_t endpoint_id, uint32_t cluster_id,
        uint32_t attribute_id, esp_matter_attr_val_t *val, void *priv)
{
    if (type != attribute::PRE_UPDATE) return ESP_OK;

    if (cluster_id == OnOff::Id && attribute_id == OnOff::Attributes::OnOff::Id) {
        bool on = val->val.b;                 // → UART: 0x11 / 0x10
    } else if (cluster_id == LevelControl::Id) {
        uint8_t level = val->val.u8;          // 0~254 → DIM 단계 변환
    } else if (cluster_id == ColorControl::Id) {
        uint16_t mireds = val->val.u16;       // Mired → K → CCT 스케일
    }
    return ESP_OK;
}

void app_main() {
    node::config_t node_config;
    node_t *node = node::create(&node_config, app_attribute_update_cb, NULL);

    color_temperature_light::config_t light_config;  // Device Type 0x010C
    endpoint_t *ep = color_temperature_light::create(node, &light_config,
                                                     ENDPOINT_FLAG_NONE, NULL);
    esp_matter::start(app_event_cb);
}
